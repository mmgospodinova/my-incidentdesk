## Goal
Customer-facing incidents are raised one priority level whenever they are opened, including nights and weekends.

## Steps
1. Update `incidentdesk/priority.py` so `compute_priority` raises a customer-facing incident one level without consulting business hours.
2. Update `tests/unit/test_priority.py` with one separate test for each customer-facing major-incident example in the rules table: Tuesday 14:00, Tuesday 23:30, and Saturday 10:00; leave the existing severity, P1, maintenance, and time-zone assertions intact.
3. Update `CHANGELOG.md` with one plain-language Unreleased note that customer-facing incidents receive the higher priority at any hour.
4. Leave `incidentdesk/routing.py` and `tests/unit/test_routing.py` unchanged.

## Tests
- Tuesday 14:00, major, customer-facing: the Tuesday daytime test in `tests/unit/test_priority.py` asserts `P1`.
- Tuesday 23:30, major, customer-facing: a separate Tuesday night test in `tests/unit/test_priority.py` asserts `P1`.
- Saturday 10:00, major, customer-facing: a separate Saturday test in `tests/unit/test_priority.py` asserts `P1`.
- Routing remains unchanged: run `pytest tests/unit/test_routing.py` and verify all existing tests pass without modifying the routing code or tests.
- Existing priority behavior remains covered: run `pytest tests/unit/test_priority.py` to verify all priority tests, including P1 clamping and maintenance, still pass.

## Risks
- Removing the business-hours condition from customer-facing priority calculation could unintentionally affect non-customer-facing incidents, P1 clamping, or maintenance adjustment; the existing priority tests will expose those regressions.
- Reusing `compute_priority`'s time-zone-independent result for stored or downstream incidents could imply broader migration behavior; this work only changes priority computation for newly opened incidents.
- A routing regression would be visible as a failure in the unchanged `tests/unit/test_routing.py` suite.

## Out of scope
Incidents that are already stored, routing behavior, and `is_business_hours` behavior or implementation.
